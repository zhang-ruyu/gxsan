# GxSan 优化方案：从「看数据」到「给建议」

> 版本：2026-08-04 初稿
> 触发：用户普通用户视角 Top10 需求 + 3 条吐槽 + 总结论
> 关联：多账户体系已于本日彻底删除（见提交记录），本方案建立在其后的"单一持仓 + 建议引擎"架构之上

---

## 0. 背景与核心论断

用户原始诉求（普通用户视角）：

**🥇 Top5（最想要）**
1. **Dashboard 总览** —— 一眼看清"我的退休金进度到哪了"
2. **行动提示** —— 明确告诉我"现在该买 / 卖 / 等"，别只给数据
3. **分红到账记录** —— 真实到账的历史，而不只是"计划分红"
4. **持仓成本一键修正** —— 分红除权后成本自动下调（或一键手动）
5. **导出** —— 数据能导出来（CSV / Excel）

**🥈 Top5（其次）**
6. 股价走势图（历史价格 + 估值带）
7. 回测（策略历史表现）
8. 多设备同步（云同步 config）
9. 股利日历提醒（哪天除权、哪天到账，提前提醒）
10. 暗色模式

**🤔 3 条吐槽**
- 数据太散，找不到重点
- 术语太多，看不懂
- 没有"下一步该干嘛"

**💡 总结论（用户原话）**
> 从"看数据"到"给建议"，是这个工具最大的体验跃迁空间。

**当前 GxSan 的能力边界**
- 能：单股估值/信号、持仓市值盈亏、YoC、按自然年分红汇总、养老倒推本金、房产→股权对比
- 不能：主动告诉用户"现在该买/卖/等多少"、记录真实分红到账、跨设备同步、可视化走势

---

## 1. 产品定位重定

| | 旧定位 | 新定位 |
|---|---|---|
| 一句话 | 分红数据浏览器 | 个人分红养老操盘助手 |
| 用户每次打开得到 | 一堆指标 | 一个明确的"下一步动作" |
| 核心问题 | 我持有啥、赚多少 | 我现在该干嘛、离目标还差多少 |

> 所有新功能都应服务于"降低决策门槛"：把已有的信号/估值/网格，**翻译成人话指令**。

---

## 2. 分阶段路线图

### 阶段一（建议优先，约 1–2 周）：建议引擎 MVP

> 目标：把已有的 `strategy.DividendStrategy` + 网格，变成用户能直接照做的指令。复用度最高、成本最低、价值最大。

**1.1 Dashboard 总览页（取代当前 Home 的堆砌）**
- 退休金进度条：当前年化分红 ÷ 目标月分红×12 → 进度 %
- 三张核心卡：组合股息率 / 年化分红 / 距离目标还差多少本金
- 今日/本周"待办动作"列表（数据来自 1.2 行动建议）

**1.2 行动提示（Action Advisor）**
- 对每只持仓输出 `买 / 卖 / 持有` + 建议金额或股数 + 一句话理由
- 在 Dashboard 与 Detail 顶部展示"建议卡"
- 数据契约：复用现有 `model.StockDetail` 的 `signal / reason / cheap_price / fair_price / expensive_price`，新增 `model.ActionSuggestion{ Action, SuggestAmount, SuggestShares, Reason }`
- 金额建议来源：网格档位 `g.Amount` / `g.Yield` 已具备，无需新数据源

**1.3 持仓成本一键修正**
- 分红除权后，持仓成本应随之下调（或累计填权收益）。提供"按最新分红记录自动下调 AvgCost"按钮
- 后端：`config.Manager.AdjustCostByDividend(code)`；前端 Portfolio 编辑弹窗增加"按分红修正成本"
- ⚠️ 必须保留"原始买入成本"快照，避免把填权收益误算成亏损

---

### 阶段二（现金流真实化，约 2–3 周）

**2.1 分红到账记录（真实历史）**
- 现有 `GetDividendHistory` 是"每股分红预案"，不是"我实际到账"
- 需新增：按 `持仓股数 × 每股 × 到账日` 计算真实到账金额，落盘到 `data/` 或 config 的 `received_dividends`
- 视图：时间线/列表 + 累计已收分红 + 年化实现率（实际 ÷ 计划）

**2.2 股利日历 + 提醒**
- 抓取除权除息日、股权登记日、派息日（EastMoney 相关接口可扩展）
- 日历视图 + 提前 N 天本地提醒（系统通知 / 桌面托盘，Wails 支持）
- 依赖：2.1 的到账数据结构

---

### 阶段三（可读性与可携带，约 1–2 周）

**3.1 导出 CSV / Excel**
- 持仓、分红汇总、到账记录、养老测算均可导出
- 后端新增 `GetExport(kind)` 返回 CSV 字符串；前端下载（Wails 用系统文件对话框）

**3.2 暗色模式**
- 前端已用 CSS 变量（`--text-muted` 等），加主题切换 + 持久化到 `localStorage`；Wails 端读系统主题

**3.3 术语降噪**
- 全站文案审查：`YoC` → "成本股息率（已回本比例）"、估值带 → "便宜/合理/贵"、信号 → "建议买/卖/等"
- 给每个指标加 hover 解释（tooltip）

---

### 阶段四（深度与多端，约 3–4 周，按需）

**4.1 股价走势图 + 估值带**
- 前端引入轻量图表（ECharts / Chart.js），叠加 cheap/fair/expensive 三条线 + 历史价格 + 分红标记
- 依赖：行情接口需补历史 K 线（当前 `EnrichStock` 只有即时价 + PE/PB）

**4.2 回测**
- 对选定股票/策略，用历史分红 + 价格模拟"如果 X 年前开始定投，现在收益"
- 复用 `plan/compound` + 历史数据

**4.3 多设备同步**
- `config.yaml` 同步到云（GitHub Gist / 自建 / OneDrive）
- ⚠️ 含持仓成本属敏感数据，需加密或仅放用户私有仓库
- 最小可行：导出/导入 + 手动同步；进阶：自动 push 到私有 gist

| 成本一键修正 (1.3) | 一 | ★★★★ | 中 | 现有分红记录 |

## 4. 风险与取舍

- **走势图 / 回测** 需要历史行情源，当前 fetcher 不强；先确认数据源成本再动手，避免阶段四阻塞阶段一~三。
- **多设备同步** 涉及隐私，默认关闭、仅手动触发；绝不自动上传含持仓成本的明文文件。
- **行动建议要"可解释"**，避免黑盒：每条建议必须带理由与数据出处（便宜价/网格档位），否则用户不会信。
- **术语降噪不等于删功能**：专业指标保留，只是给"人话"别名 + 解释，满足普通用户又不赶走进阶用户。

---

## 5. 建议落地顺序

```
先做：1.2 行动提示 + 1.1 Dashboard   （最大价值、最低成本，复用现有信号）
接着：1.3 成本一键修正
然后：2.1 分红到账记录 → 2.2 股利日历提醒
再后：3.1 导出 → 3.3 术语降噪 → 3.2 暗色模式
最后（按需）：4.1 走势图 → 4.2 回测 → 4.3 多设备同步
```

> 一句话：**先把"该买该卖"说清楚（阶段一），再把"赚到没"记清楚（阶段二），最后才做花哨的可视化与多端（阶段三/四）。**
